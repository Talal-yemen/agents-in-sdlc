GitHub Copilot をエージェントモードで使うと、コードベースを調査し、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムに確認できます。差分をインラインでレビューし、変更を個別に採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

このレッスンでは、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムに監視します。
- 提案されたファイルの編集をレビューして採用します。
- セッションの途中でエージェントに指示を送り、ハイコントラストモードと合わせてライトモードの切り替えを追加します。

## シナリオ

[レッスン 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めずに、既存のセッションを調整して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調査したファイル、実行したコマンド、提案した編集などの手順を確認できます。各ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. レッスン 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントにもう一度作業させます。
4. チャットの上部にある **Files changed** を開き、セッション中にエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツールの呼び出し (ターミナルコマンドの実行など) で許可が必要な場合、エージェントは一時停止し **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードを実装するまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは前の作業、変更したコンポーネント、スタイルの方法、local storage を使った設定の保存方法を把握しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調査し、ライトモード用の追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの作業が希望と異なる場合は (例: 切り替え UI を意図しない形でリファクタリングする場合)、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 作業中のセッションを調整すると、最初からやり直すより早くなります。追加プロンプトで変更を依頼できます。たとえば「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する」「両方の切り替えにキーボードショートカットも追加する」などです。

## 作業ファイルをレビューする

作業をコミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など、カスタムエージェントが示したアクセシビリティのパターンを確認します。
4. 内容に問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンでブランチを公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、作業中のセッションを監視し、調整しました。各ファイルの編集を確認して採用または取り消し、コンテキストを保ったまま追加プロンプトを送り、作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムに監視する
- 個々のファイルの編集を採用または取り消す
- 作業中のセッションに追加プロンプトを送って調整する

次のレッスンでは、このハンズオンでローカルのカスタムエージェントが生成した変更を公開し、プルリクエストとしてレビューします。
