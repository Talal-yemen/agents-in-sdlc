我们先为项目添加了一项小功能，但更大的更改需要更完善的流程。GitHub Copilot app 能配合组织现有的工作方式，帮助团队用正确的方法构建所需功能。从本课开始，你将通过几节课程遵循典型的智能体驱动开发流程：从议题出发生成新功能，确认代码有效、功能符合预期，最终成功将更改合并到项目中。

> [!NOTE]
> 后续功能工作流都将沿用同一个会话。通常，不同类型的文件会使用不同会话或 PR，但这里会采用简化方式，以便专注于核心概念。

本课将介绍如何：

- 从 GitHub 议题启动新的智能体会话；
- 在 **Plan** 模式中明确需求；
- 使用 **Autopilot** 模式实现新功能；
- 审查代码；
- 在浏览器画布中手动验证功能。

继续开发该功能时，你还将更新存储库指令、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 智能体并创建功能 PR。

## 场景

Tailspin Toys 的游戏目录不断扩展，访客需要按类别和发行商筛选游戏。待办议题描述了该功能，但多个类别如何组合等细节需要在编码前确定。你将使用 Plan 模式明确这些决定，然后授权 Autopilot 在限定范围内完成实现。

## 背景

将 AI 编码智能体引入开发流程，并不会改变基本原则。事实上，这些原则变得更加重要。大多数开发人员遵循的流程大致如下：

1. 打开已创建的议题，查看待完成的工作。
2. 制定构建计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述做法类似。

遵循这种标准方法，可以确保 AI 生成的代码满足既定要求，并经历与手写代码相同的审查流程。

## 会话模式

**会话模式**控制智能体的自主程度。可以从提示字段下方的下拉菜单中设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已经合并，并且本地 `main` 已更新。

1. 在侧边栏 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是一个已有议题，无需再创建。
2. 选择 **New session**，再选择基于更新后 `main` 创建的 **new working tree**。

    ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，让智能体运行 `node --version` 和 `npm --version`。如果这两个命令在终端中可用，但在会话中不可用，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。之后重试失败的操作和检查；不要只因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划让你能在 Copilot 编写代码前审查实现方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送以下提示：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并根据议题验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时应如何处理。

计划应使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。将范围限定为筛选功能的实现和测试；完成质量工作流后再创建 PR。批准计划前，请要求调整不合适的内容，并保存议题 URL 及达成一致的说明，供后续验证使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中的等效选项。确认当前模式，不要假设批准操作会自动切换模式。确认模式指示器显示 **Autopilot**。

Copilot 会开始实现功能！你会看到它按计划逐步工作、编写代码并运行测试。

> [!NOTE]
> 批准后可能会立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决环境问题，再判断检查是否完成。只停止自己启动的服务器。

## 审查并验证实现

与其他代码一样，生成的代码也需要在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 根据议题和批准的说明审查结果，包括多类别和发行商组合。检查更改是否遵循现有存储库指令。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，先解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，而且可能复用本地服务器；确认测试所用的服务器属于此工作树，而不是之前课程的服务器。

## 体验新功能

代码看起来没问题，但运行是否正常？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 稍等片刻，应用会启动，Copilot app 中也会打开浏览器窗口。
3. 选择一个类别，确认结果与类别相符。清除筛选器，再选择一个发行商，确认结果与发行商相符。
4. 组合类别和发行商筛选条件，并根据议题和已批准的计划比较结果。如果支持多个类别，还要验证约定的组合方式。
5. 尝试没有匹配游戏的筛选组合并查看空状态。清除或重置筛选条件，确认完整列表重新显示。
6. 完成后，使用以下提示，让 Copilot 停止为此会话启动的开发服务器并关闭浏览器画布：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 保留此会话以供后续课程使用

暂时不要创建或合并筛选 PR。保留此会话、工作树和分支，供第 4 到第 8 课继续使用。下一课会将自定义指令应用于筛选代码，然后添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。

## 总结与后续步骤

你使用不同的智能体模式构建并审查了功能。本课中，你：

- 从 GitHub 议题启动了新的智能体会话；
- 在 **Plan** 模式中明确了需求；
- 使用 **Autopilot** 模式实现了新功能；
- 审查了代码；
- 在浏览器画布中手动验证了功能。
